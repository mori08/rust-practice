# Git 運用メモ

このリポジトリでの git の運用ルール。学習リポジトリ（一人開発）向けの最小構成。

## ブランチ

- **main に直接コミット**する
- ブランチは切らない。実験的な書き換えや発展課題で必要になったら、その時に方針を見直す

## コミットメッセージ

- **日本語・見出し形式**で書く: `<見出し>: <本文> (#Issue番号)`
- 関連する Issue があれば末尾に `(#N)` を付ける（GitHub 上で自動リンクされる）

```
例:
段階1: ディレクトリ単発スキャンを実装 (#2)
初期セットアップ: cargo init、README、LICENSE、CLAUDE.md、学習メモ
```

- Issue のタスクをすべて完了させるコミットは、本文に `Closes #N` を含めると Issue が自動で閉じる

## コミットの粒度

- 「練習課題1つ」「段階1つ」など、**学習の区切りごと**に1コミット
- 動かない状態ではコミットしない（各コミットが `cargo run` できる状態を保つ）

## コミット前チェック

コミット前に以下を通す（CLAUDE.md の方針）:

```
cargo fmt --check && cargo clippy
```

- `fmt --check` が失敗したら `cargo fmt` で整形してから再確認
- テスト導入後（段階2〜）は `cargo test` も追加する

## Issue 運用

`notes/progress.md` と Issue で情報が二重管理になり内容が乖離したため、役割を分ける。

| | 役割 | 粒度 |
|---|---|---|
| `notes/progress.md` | 学習の記録（習得トピック・背景・次回の再開点） | 細かく。詳細はここに一本化する |
| GitHub Issue | これから作るものの単位（ゴールと受け入れ条件） | 粗く。「立てる」「閉じる」の2状態 |

- **Issue に段階ごとのチェックボックスを置かない**。進捗の更新漏れという状態を作らないため
- Issue 1つは、着手から完了まで一気に進められる大きさにする（1〜2セッション程度）
- 本文には「背景」「ゴール」「受け入れ条件」を書く。学習リポジトリなので「学習トピック」も添えるとよい
- 発展課題は着手を決めた時点で起票する。思いつきの段階では立てない
- コミットメッセージ末尾の `(#N)` で紐づける。Issue を閉じるコミットは本文に `Closes #N` を書く
- 完了したら Issue を閉じる。学習内容は `notes/progress.md` に転記する
